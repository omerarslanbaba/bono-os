# UYAP Extension 0.3.9 — Safe rollout and rollback

## Scope
This procedure applies only to the BONO UYAP Chrome extension. It does not deploy or replace the native EXE, database, archive, or case files.

## Current safety assumptions
- Download lane remains manually paused (`uyap_manual_download_pause=1`).
- Global automatic PDF batching remains disabled.
- 0.3.9 must not auto-reload an open UYAP tab.
- A `login_required` Core state is preserved until a real authenticated UYAP observation is seen.
- A HTTP 200 auth probe containing `errorCode` or `error` is not accepted as authentication.

## What extension reload does
Reloading an unpacked extension restarts its background service worker. Existing content-script contexts may no longer be usable by the new runtime until the UYAP tab is reloaded. Any query already claimed before reload may therefore lose its result path and remain `running` until Core stale-command recovery returns it to `queued` after 3 minutes.

For that reason, **do not reload the extension while a UYAP command is running.**

0.3.9 migration no longer calls `chrome.tabs.reload()`. It stores `bonoBridgeNeedsTabReload=true`. The user performs the UYAP-tab F5 only after the rollout preconditions are satisfied. A new `probe_ready` clears the flag.

## Safe deployment preconditions
1. User explicitly approves the live test.
2. `manualDownloadPaused=true` and document state reports `paused_manual`.
3. `document.pdf` has no new dispatch after the pause timestamp.
4. Core has no `running` UYAP command.
5. Prefer deploying while Core is already `login_required`; this prevents new query claims during extension replacement.
6. Record:
   - current extension source commit / backup reference: `3ad9864` for 0.3.8
   - target commit containing 0.3.9
   - queued/completed CBS counts
   - last query dispatch timestamp
   - last PDF dispatch timestamp

## Deployment
1. Replace only the approved extension source files from the 0.3.9 commit.
2. Reload BONO OS Bridge in `chrome://extensions`.
3. Do **not** expect or trigger automatic UYAP tab reload.
4. Verify Core is still `login_required` and download is still manually paused.
5. Manually F5 the UYAP tab once.
6. User logs in manually if UYAP requires authentication.
7. Wait for a genuine authenticated 2xx JSON observation without `errorCode/error`.
8. Confirm session becomes `ready`.
9. Leave download manually paused and observe query lane for at least 5 minutes.

## Acceptance criteria
- No `document.pdf` dispatch while manual download pause is active.
- CBS/query completed count advances for at least 5 minutes.
- Query cadence resumes after the normal endpoint interval/backoff.
- At most one query command is `running` at a time.
- No single command id is dispatched twice concurrently.
- Alarm wake plus interval poll does not create two running query commands.
- A deliberately stale simulated query produces one timeout/failure report and one replacement claim.
- `login_required` does not clear on a 200 response whose sample keys contain `errorCode` or `error`.
- No global PDF queue is generated by `document.list`.
- Native EXE is unchanged.

## Stop conditions
Stop the test and do not resume query execution if:
- any PDF dispatch occurs while manual pause is active;
- two query commands are simultaneously `running`;
- the same command id is observed as concurrently dispatched twice;
- repeated 401/403 responses occur;
- session flips to ready without a genuine authenticated observation;
- Chrome/UYAP becomes unstable after extension reload.

## Rollback source
Known pre-0.3.9 extension source is available at commit:
`3ad9864f5d4af726f6348fc8fb777939cb095efd`

Restore:
- `extension/background.js`
- `extension/content.js`

`page_probe.js` is not part of the 0.3.9 query-wake change.

## Rollback procedure
1. Keep downloads manually paused.
2. Stop acceptance testing; do not start new manual batches.
3. Wait until Core reports no UYAP command with `status='running'`.
4. Restore `background.js` and `content.js` from commit `3ad9864`.
5. Reload BONO OS Bridge in `chrome://extensions`.
6. Because 0.3.8 has its older migration behavior, perform rollback only after step 3; an UYAP-tab reload may occur.
7. If UYAP is logged out, leave Core at `login_required` and let the user log in manually.
8. Confirm manual download pause is still active.
9. Confirm no PDF dispatch occurred during rollback.
10. Verify query behavior separately before any download resume.

Rollback never restores or rewrites `bono.db`, case data, archive data, document files, or the native EXE.
